# EVO: small upstream-portable chat-list optimization

Owner: Anton, Slack BBC thread1793161110.426789, 2026-10-28 scope extension.
Baseline: `5c46c3a4aa116cec5120b30b0f165f4a6c9111b7`.

## Selected change

The old `fetchChats` query joined Contact/Chat and carried the full message
projection through DISTINCT ON for the entire selected history. The candidate
selects only latest message IDs first, then hydrates those rows. It preserves
instance isolation, optional remoteJid and timestamp bounds, LIMIT/OFFSET,
missing contacts/chats, native message content and the current response shape.
Ties at identical timestamps retain the existing unspecified selection contract;
this patch does not introduce a new ordering policy.

Only one runtime method changes: 11 added / 7 removed lines. No extra cache,
worker, dependency, schema/index, queue or provider-identity change. Previously
released lightweight inventory, bounded ingress and lazy diagnostic formatting
already cover other obvious hot paths; they are not counted as new work.

## Local proof

tables, 1,000 chats / 100,000 messages with 3.2KB synthetic text payloads. Four

The baseline outlier is retained, not silently discarded; these are not p95.

Real SQL contract also checks two instances sharing a peer, incoming/outgoing
projection, groups, missing Contact/Chat, contact-only exclusion, exact peer,
timestamp-window selection and pagination. All temporary tables disappear when
the owned session closes. No production or WhatsApp call is part of the test.

## Reproduce / rollback

Run `npx tsx --test tests/chat-list-projection.test.ts` for the default unit path.
Opt-in SQL test accepts only `EVO_CHAT_LIST_SYNTHETIC_URL` at hostpostgres,
databasepostgres; it creates only session-local tables. Set
`EVO_CHAT_LIST_BENCHMARK=1` and `EVO_CHAT_LIST_BASELINE_SOURCE` to the saved exact
baseline channel.service.ts to compare. An optional `EVO_CHAT_LIST_PLAN_PATH`
retains synthetic plans. Never redirect this test to production.

Revert the one method/previous immutable image to roll back; data is unchanged.
PR/main/lab/release/readback are separate states, not implied by these results.
